01

一、背景与目标

起点

仓储管理系统（WMS）与运输管理系统（TMS）经过二十余年发展，功能已相当完备，但其交互范式始终停留在"人适应系统"阶段。一线操作者需要熟记数十个菜单入口、上百个字段含义，并在多个单据、多个系统之间来回切换才能完成一次完整作业。系统越强大，学习成本越高，操作链路越长，人为差错的概率也随之上升。

与此同时，大语言模型驱动的业务 Agent 在理解意图、编排流程、调用工具、处理非结构化信息方面展现出成熟能力。这为重构 WMS/TMS 提供了全新技术路径。

本方案提出的核心判断是：Agent 将成为下一代 WMS/TMS 的主交互形态与执行主体。需要明确区分两个概念——"Agentic"意为给现有系统加装智能层，本质仍是换皮；本方案追求的是 Agent，即系统本身成为可承担职责的智能体。二者差别不在技术，而在决策权归属：前者系统替人执行，后者系统替人决定。

方案目标包括四点：

  1. 将高频作业的操作步骤压缩为自然语言指令，降低使用门槛；
  2. 将散落于多个系统与单据之间的作业流程，由 Agent 自动串联编排；
  3. 将异常发现、取证、归因、处置构建为主动闭环，减少被动等待；
  4. 在不推倒底层系统的前提下完成渐进式演进，保护既有投资。
02

二、产品定位与设计原则

定位

2.1 产品定位

Agent WMS/TMS 定位为叠加在现有系统之上的智能作业层，而非替代品。底层 WMS/TMS 继续承担事务处理、库存账务、单据流转等可靠性要求极高的执行职责；Agent 层承担理解、决策、编排与交互职责。二者通过标准化工具接口解耦，可独立演进。

从演进终点看，Agent 层将从"辅助工具"逐步成长为"数字劳动力"——拥有岗位、权限、绩效与责任边界，人由操作者转变为管理者和例外审批者。这一定位决定了后续所有设计不以"更方便地操作旧系统"为目标，而以"把人从操作循环中移出"为目标。

2.2 设计原则

原则内涵
执行与智能分离底层系统负责可靠执行，Agent 负责理解与编排，职责边界清晰
人在回路所有写操作先出变更预览，经人工确认后提交，关键操作双人复核
数据不可幻觉库存、单据等事实性数据只能来自工具调用结果，不由模型生成
权限继承Agent 权限是操作人权限的子集，不允许越权执行
全程可追溯每一步决策的依据、调用的参数、产生的结果均留痕，可复盘可审计
03

三、范式革命：从工具到劳动力

战略

自然语言输入只是交互改良，不是范式革命——它改变了"人怎么告诉系统"，没有改变"系统是什么"。判断一个创新点是否够得上革命，有两把尺子：决策权是否从人转移到系统，以及人是否被移出操作循环。按这两把尺子衡量，有四个真正的革命点。

3.1 自愈系统：从「记录系统」到「行动系统」

传统 WMS/TMS 本质是记录系统（System of Record）——货动了人去记，差异出了人去查。革命点是系统自己闭环：发现差异 → 拉取证据链 → 归因 → 在低风险边界内自动修复 → 只把需要人拍板的推给人。

以盘亏为例：传统系统是生成一张差异表等人处理；Agent 是查到昨夜出库未过账、自动补过账、库存恢复，并把完整证据链推送给人，人只需知悉或推翻。人从操作者变成例外审批者，这是质变而非量变。企业在盘点事务报表、差异归因方面积累的数据资产，正是这套自愈能力的数据地基。

3.2 预测性干预：时间轴整体前移

现有系统都是事后响应——单来了才拣货，货到了才收货，盘点亏了才查。Agent 时代可以事前干预：

场景传统（事后响应）预测式（事前干预）
库存缺货后触发补货预测三日后断货，提前调拨
运输延误后通知客户预测承运商排车不足，提前改派
库位爆仓后临时找位预测明早到货峰值，今晚预移库
盘点月度盘点查差异按风险频率动态抽样，高风险区每日盘

这一条最容易被低估：它把 WMS/TMS 从"业务流程的执行者"变成"业务的主动调控者"，是角色定位的根本变化。

3.3 数字劳动力：软件第一次有了「岗位」

传统系统只有功能，没有岗位。革命点是 Agent 拥有自己的身份、权限、绩效与责任边界：

  • 有岗位：入库、盘点、调度等 Agent 各管一摊，职责明确；
  • 有绩效：准确率、响应时长、人工接管率可量化考核；
  • 有管理幅度：一个主管从管十名操作员，变成管三个 Agent 加两名异常专员；
  • 有责任边界：Agent 权限是人的子集，出错追溯到授权人。

组织形态会因此改变。这不是功能升级，而是"软件即劳动力"——WMS/TMS 从 IT 系统变成人力编制的一部分。

3.4 流程涌现：从「固化」到「动态生成」

传统流程在开发时写死，改一条规则要发版。Agent 时代的流程是根据目标实时生成的：同样一句"把这批货发走"，A 仓因月台紧张走越库直发，B 仓因质检未完成走暂存——路径不同，目标一致。流程从"代码里的常量"变成"每次的因变量"。下线即走判定、拆组垛策略，本质就是这类动态路由的雏形。

3.5 次级创新与反向检验

除上述四点外，还有三类重要创新：决策资产化（每次纠偏沉淀为策略，系统越用越懂这个仓库）、仿真预演（执行前在数字孪生跑一遍）、多 Agent 协商市场（承运商竞价、库内任务抢单）。

检验一个点是否真革命的方法很简单：去掉自然语言界面，这个价值还在吗？ 在，才是真革命；不在，就是换皮。聊天问答、语音录入、智能表单填充、报表自然语言查询都属于第一层——它们改善体验，但不改变系统性质。自愈、预测、岗位化、动态流程去掉聊天框照样成立。

革命性的度量不是"AI 有多强"，而是人从操作循环里退出到什么程度。按退出程度排序：自愈 > 预测 > 岗位化 > 动态流程 > 自然语言输入。但这四件事的前提是数据可信、责任清晰、风险边界明确。没有这三样，自愈就是乱修，预测就是瞎猜。所以落地顺序反而要倒着来——先把只读查询做扎实攒信任，同时埋好自愈需要的证据链数据，等数据密度够了再开自治。革命不在界面上，在数据地基上。

四、终局推演：从「系统」到「协议」

终局

前三章回答的是"Agent 如何把旧流程跑得更好"——单据还在，只是 Agent 帮你填；系统还在，只是 Agent 替你跨；盘点还在，只是差异归因更快。这些都是在同一副骨架上贴智能。若把推演推到终局，问题应当反过来问：哪些旧结构会彻底失去存在必要。

4.1 一个根：记录与现实的时差

今天 WMS/TMS 中一切"中间结构"，本质都在弥合同一个缺口——记录追不上现实。货已经动了，账还没动；一个业务现实被切成三段，分别记在三个系统里；记录是给机器看的，人要操作就得翻译一遍；账实对不上，只能定期人工对齐。

中间结构它在补的缺口消亡条件
单据货已动、记录未动，用单据补时差动作即事实，物理变化实时落为不可变事实
系统边界一个现实被切成 WMS/TMS/ERP，靠接口缝回统一运营本体，各系统降级为同一本体的视图
界面与审批记录不面向人，需翻译、需确认人只定义约束，Agent 在约束内自治
对账与盘点记录与现实漂移，需周期性对齐事实流持续收敛，账实偏差实时可见

根一旦拔掉——视觉识别、RFID、称重、位置信号让动作本身成为事实——上表所有中间结构同时失去存在理由。这不是四个独立改进，而是一个原因塌出的四个坑。

4.2 三个消亡

单据消亡。 物理动作本身就是数据：视觉识别、RFID、称重、温度传感器与位置信号直接捕获"这箱货进了哪个库位"。系统维护的是一张持续对齐物理世界的数字孪生，单据从"业务载体"降级为"按需生成的监管视图"。对盘点而言这是根本冲击——若每次存取都实时更新事实，账实恒同步，"定期盘点以发现差异"这一职能将不再必要；差异归因退化为毫秒级的实时异常检测。

系统边界消亡。 WMS、TMS、ERP、MES 的分界是软件架构的历史产物，不是业务本身的需要。当 Agent 理解业务语义，不再有"在 WMS 建库存、在 TMS 建运单、在 ERP 记账"，只有一个统一的企业运营模型，WMS/TMS 只是它的不同视图。

同样直接相关：接口对接规范、报文差异比对、幂等键与回传字段——在终局里都不存在。系统之间不再"对接"，因为它们本来就是一个东西。

界面消亡。 前文把自然语言当作入口，其实对话也仍是界面。终局是 Agent 感知到异常即行动，人只在红线被触碰时收到通知。界面从"操作入口"退化为"治理面板"——人看的不再是库存明细表，而是"昨日多少决策被自主完成、哪些触碰了红线"。

维度加装智能层系统即智能体（终局）
单据Agent 帮人填写不需要单据
系统Agent 跨系统操作没有多个系统
界面自然语言输入没有输入这个动作
人审批者约束设定者

4.3 两个不可替代

物理世界提供事实，Agent 完成执行，人手中只剩两件永远无法外包的东西：

  • 意图：目标、约束、红线由人定义。人说的是 What 与 Why，永远不是 How。Agent 可以决定怎么走流程，但不能决定走向哪里、哪些路不能走。
  • 信任：决策必须可审计、责任必须可回溯。授权可以交给 Agent，但责任不能。每一次自主决策都要能回答"依据什么、调用了什么、产生了什么"，并锁定到具体授权人。

因此终局产品的两个面不是功能菜单，而是意图入口与信任账本。前者让人表达目标与边界，后者让每一步自主行为可被验证、可被追责。

4.4 产品形态变性：从系统到协议

这是前面所有版本都没有跨过去的一步：产品不再是"系统"，而是"协议"。

维度系统协议
客户怎么用买来操作参与制定并遵守
卖什么功能许可、订阅规则制定权、认证权、仲裁权
客户是谁仓库、车队任何有物理运营的组织
护城河功能多、界面顺定义事实流格式、业务本体、Agent 交接契约与审计证据标准

谁定义这四件事，谁收租。类比：导航仪消灭了纸质地图，但赢家不是地图厂，而是定义路线协议的那批人。这已不是软件生意，而是标准生意。

4.5 品类自毁

一个反直觉的结论：Agent WMS 做成功的那一天，就是 WMS 作为独立品类消失的那一天。 收入形态将从 License 或订阅，被迫转向按自主决策次数、按事实流托管量计价。

按这把尺子回看当下的交付物——功能清单、权限矩阵、单据字段、报表样式——本质上是在给一栋正在拆的房子做精装修。这话刺耳，但它是"再深一层"必然得出的判断。需要强调：这不是否定当下工作的价值，而是提醒每项投入都要回答"它在终局里还成立吗"。

4.6 方向判据，而非路线图

必须泼一盆冷水：上述终局至少十年，前提是物理世界数据采集密度到位——没有视觉、RFID 与传感器铺满，"动作即事实"就是空想。因此它不应被写进路线图，而应作为方向判据：用它判断今天该做什么。

按终局倒推，现在最该做的只有两件事：把操作变成可机读的事实流，把业务规则从代码里抽成 Agent 可理解的策略。这两件做了，后面所有演进都顺；没做，都是局部优化。

五、终局倒推的投入判据

判据

5.1 现有产出的资产重估

现有产出终局价值调整方向
盘点事务报表、差异归因资产：事实流与实时异常检测的地基补事件语义、时间戳、证据链字段，不止出汇总表
接口对接规范资产：语义契约的雏形把字段映射升级为本体定义，不只写报文格式
权限矩阵半成品：红线定义的雏形从"角色能点什么"改为"Agent 可自主到什么边界"
功能域地图负资产：描述的是旧骨架保留，但改标为"待消亡清单"并按消亡难度排序
单据字段、表单交互纯负资产只做监管合规必需的最小集，不再优化填报体验

5.2 判断三问

以后设计任何功能，先问三句：

  1. 它记录的是动作，还是动作的结论？记录动作是资产。
  2. 它服务的是人操作，还是 Agent 理解？面向 Agent 理解是资产。
  3. 它沉淀的是一次性数据，还是可复用策略？沉淀策略是资产。

三问都落在后者，才算在修终局；否则是在装修旧房子。

5.3 对路线图的修正

第十一章路线图的顺序与革命性排序相反，这一点在终局视角下更加明确：自愈、预测等能力依赖前两期积累的可信数据与证据链，所以放在后期。终局判据不改变这一顺序，但改变每一期的验收标准——不仅看"Agent 完成了多少操作"，更要看"沉淀了多少可机读事实与可复用策略"。

一句话概括：革命不在界面上，甚至不在 Agent 上；革命在于让旧结构不再必要。

06

六、总体架构

五层

系统采用五层架构，自上而下依次为交互层、Agent 编排层、领域 Agent 层、工具层与数据系统层。

层级组成职责
交互层自然语言对话、PDA/语音、企业微信/钉钉、调度大屏多模态接入，使用户以最自然的方式表达意图
Agent 编排层意图识别、任务规划、工具编排、校验与回滚理解用户目标，拆解为可执行步骤，调度工具并校验结果
领域 Agent 层入库、出库、盘点、运输、异常 Agents各司其职，复杂场景下多 Agent 协同作业
工具层库存/库位查询、单据创建与过账、任务下发、承运商与路由将每个系统操作封装为带契约的可调用工具
数据系统层WMS 主数据、库存账与单据、TMS 运单、ERP/MES 接口提供事实数据与执行能力

交互层解决"怎么说"的问题：用户既可以在电脑前用自然语言对话，也可以在仓库现场用 PDA 扫码加语音，管理者还可以在大屏上直接下达调度指令。所有输入最终被统一为结构化的意图描述。

编排层是系统大脑。它接收意图后，先补全缺失参数（如从用户默认仓库推断库区），再将目标拆解为步骤序列，逐步调用工具，并对每一步结果进行校验。若某步失败，可按预设策略回滚或转人工处理。

工具层是整个设计的技术基石。底层系统的每一个原子操作——查询库存、创建单据、分配库位、下发任务、叫车、选承运商——都被封装为具备明确定义入参、出参、幂等键与失败补偿机制的工具。Agent 只能通过这些工具访问系统，无法直接读写数据库，从机制上杜绝了幻觉数据写入业务系统的可能。

07

七、WMS/TMS 功能域与 Agent 能力地图

19 域

本章按行业通用功能划分，逐一列出 WMS 与 TMS 的功能域，明确每个域中 Agent 可承担的操作与建议目标成熟度。功能域是工具封装的边界，也是分期落地的粒度。

7.1 成熟度分级定义

级别定义典型行为人在回路要求

08

八、核心操作范式

三种

Agent 上的操作可归纳为三种范式，分别对应不同的触发方式与自主程度。

8.1 对话式操作：人主动说，Agent 代为执行

用户以自然语言描述目标，Agent 解析意图后先给出可审阅的执行计划，用户确认或纠偏后才真正提交。以收货上架为例：

用户：A 区今天到的那批雪花纯生，批号 20261123，先收了上架。
Agent：查到 ASN 单 SO20261123008，500 箱，昨日到货预告。拟定执行：
      生成收货单 → 分配到 A-01-03 至 A-01-05 → 下发上架任务给叉车工 7 号。
      是否确认？[确认] [修改库位] [取消]
用户：确认。
Agent：已执行。收货单 RK20261123031，3 张上架任务已下发，库存已更新。

关键在于中间步骤——Agent 不直接改动数据，而是先输出可审阅的执行计划。用户只需确认或纠偏，无需自行填制表单、记忆字段。

8.2 事件驱动式操作：Agent 主动发现并处置

Agent 持续监听业务事件与数据异常，一旦发现异常即自动完成取证、归因，并向人给出处置建议。以盘亏为例：

Agent：昨夜循环盘点发现 A-03-02 盘亏 12 箱。已拉取近 7 天出入库流水：
      疑似 11 月 22 日晚班出库未过账（单据 OUT2231 状态为"已发运未过账"）。
      建议处置：①补过账 ②生成差异调查单 ③忽略（标记为已知损耗）。请选择。

这是传统系统难以实现的闭环能力——将"异常发现 → 取证 → 归因 → 建议处置"串联为一条自动链路。企业在盘点事务报表、差异归因方面积累的数据资产，恰好构成这套 Agent 的高质量数据源。

8.3 多 Agent 协同：跨系统端到端作业

面对跨越 WMS 与 TMS 的复合任务，多个领域 Agent 通过编排层协同。例如用户下达"把今天发往宁波方向的订单安排出库发运"，WMS Agent 负责查询库存与拣货进度，运输 Agent 负责计算体积重量、选择承运商、预约车辆与月台，二者就交接时间与月台资源协商一致后，共同完成端到端作业，用户无需在两个系统间反复切换。

协同的关键不是让两个 Agent 自由对话，而是由编排层定义交接契约：WMS 侧输出"已备货清单 + 可用月台 + 最早交接时间"，TMS 侧回传"承运商 + 车牌 + 预计到月台时间"。任何一侧无法满足时，编排层负责回退与改派，而不是让 Agent 自行妥协。

九、关键设计机制

五项
机制设计要点
工具契约每个系统操作封装为带 schema 的工具，具备入参校验、幂等键与失败补偿；Agent 只能调用工具，不能直接写库
上下文记忆记忆用户角色、常用仓库、默认承运商与历史纠偏习惯，逐步减少每次需要显式说明的信息量
权限继承Agent 权限恒为操作人权限的子集；主管可过账则其 Agent 可过账，普通仓管员无法借 Agent 越权
人在回路所有写操作先出变更预览，确认后执行；高危操作（库存过账、单据作废）要求双人复核
可解释可追溯每一步决策记录依据——依据哪条规则、哪张单据、哪次盘点，事后可完整复盘

这五项机制共同构成系统的可信基础。其中工具契约与人在回路是硬约束，直接决定系统能否被放心地用于生产环境；上下文记忆与可解释性则决定系统的体验上限与长期演进能力。

权限继承需要落到功能域粒度：系统应维护"角色 × 功能域 × 操作类型"三维矩阵，例如仓管员可读库存、可创建收货单，但不可过账；运输调度可选承运商、可下达运输指令，但不可修改运价。Agent 在执行任何工具前先查该矩阵，查询结果为否时直接拒绝，不进入预览环节。

十、风险分级与执行闭环

门禁

系统的每一次操作请求都经过统一的五步执行链路：理解意图 → 编排计划 → 风险门禁 → 调用工具 → 校验回写。

风险门禁是整条链路的安全内核，按操作性质实施三级管控：

操作级别典型场景管控策略
只读查询查库存、查单据、查报表自动执行，直接返回结果，不打断用户
一般写操作创建单据、下发任务生成变更预览，人工确认后提交，支持一键撤销
高危操作库存过账、单据作废双人复核，全程留痕，不可撤销操作需二次确认

按功能域看，高风险操作集中在三处：库存过账与调整（库存域）、单据作废与反审核（入库/出库/运输订单域）、运价与运费修改（费用域）。这三类工具在契约中须显式标注 risk: "high"，并在门禁层强制走双人复核，不接受用户口头授权跳过。

这套分级机制兼顾了效率与安全：高频低风险的查询完全自动化，不产生额外交互负担；而产生业务后果的写操作则被有效管控，将责任链条锁定到具体的人。

十一、实施路线图

四期

建议按四期推进，从低风险场景切入，逐步建立信任、扩大范围，避免一次性大规模替换带来的风险。每期明确覆盖的功能域，以域为单位验收。

阶段功能域范围核心能力风险等级业务价值
一期WMS 库存、报表查询；TMS 报表分析只读助手：自然语言查询库存、单据与报表低立即见效，快速建立用户信任，积累真实语料
二期WMS 入库、出库、基础主数据；TMS 运输订单、运力、调度、装车发运辅助执行：带确认的单据创建、任务下发、承运商选择中免去手工填表，显著缩短操作链路
三期WMS 库内作业、接口集成、包装辅料；TMS 在途、签收、异常处理主动 Agent：异常巡检、盘亏归因、延误预警、回单催收中从被动响应转向主动发现与处置
四期跨 WMS/TMS/ERP 全域协同多 Agent 协同：端到端出入库发运、运费对账高实现跨系统端到端作业自治

一期从只读查询切入是最稳妥的路径：既不涉及数据写入，风险可控，又能让用户在真实场景中建立对 Agent 输出准确性的信任，同时为后续阶段积累宝贵的领域语料与纠偏数据。三期围绕盘亏归因的主动 Agent，是企业在盘点事务与差异分析方面积累最深、最具差异化优势的场景，建议作为重点投入方向。

每个功能域的落地需同时交付三件产物：工具契约（schema 与风险级别）、权限矩阵条目（角色 × 域 × 操作）、验收用例（正确路径、异常路径、越权路径）。三者齐备方可进入该域的下一阶段。

需要强调的是，路线图的顺序与革命性排序相反：自愈、预测等革命能力放在三期之后，不是因为它们不重要，而是因为它们依赖前两期积累的可信数据与证据链。先把地基打牢，再开自治。

十二、主要风险与应对

六类
风险表现应对措施
模型幻觉虚构库存数量或单据信息事实数据强制来自工具调用结果，每个数字可溯源到源单据
责任边界模糊Agent 误操作后责任难界定全程留痕、人在回路、权限继承三重机制锁定责任到具体操作人
现场可靠性不足网络或模型延迟影响高频实时作业收货、拣货等高频作业仍走 PDA/语音链路，Agent 前期定位为辅助位

十三、预期产出与衡量指标

收束

方案完成后，预期形成一套可落地的 Agent WMS/TMS 产品能力：覆盖主要作业场景的自然语言交互、标准化工具接口体系、风险分级管控机制，以及跨系统多 Agent 协同能力。

建议在推广过程中持续跟踪以下指标，以量化方案价值：

  1. 作业效率：单笔典型作业的平均耗时下降幅度；
  2. 操作门槛：新员工独立上岗所需培训周期缩短幅度；
  3. 差错率：因操作失误导致的单据错误与库存差异下降幅度；
  4. 异常响应：从异常发生到完成处置的平均时长缩短幅度；
  5. 用户采纳：Agent 月活跃用户数与自然语言操作占比；
  6. 功能域覆盖：已上线 Agent 能力的功能域数量占规划域数量的比例；
  7. 自治程度：无需人工介入即可完成的作业占比，衡量"人从操作循环中退出"的实际进度。

综上，Agent WMS/TMS 的核心不是给旧系统加装对话界面，而是以工具化为手段、以风险管控为底线、以记忆与可解释为体验上限，构建一层真正理解业务、可放心托付的智能作业层。但把推演推到终局，连这层作业层本身也是过渡形态——当记录追上现实，单据、系统边界与界面将依次消亡，只剩意图与信任两件事永远属于人。产品形态的终点不是更好的系统，而是一套关于事实、语义与责任的协议；今天最重要的投入，不是把旧流程做得更顺，而是让旧流程逐步失去存在的必要。
